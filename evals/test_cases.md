# 🛡️ Dialectic · 驳真 自动化评测基准用例 (Evals Suite)

本测试集用于验证「驳真 (Dialectic)」在面对不同产品与商业构想时，能否准确触发入口分流、执行硬门禁检查、避开常见思维偏见，并输出符合规范的审查结果。

---

## 🧪 用例 1：C 端单点功能虚荣膨胀 (极速两问自检卡验证)

- **输入提示词**：
  > “我想在我的桌面轻量效率小工具里增加一个‘用户活跃等级与每日徽章打卡’系统，希望能大幅提高用户打开率和留存。”
- **预期路由**：
  - [x] 自动分流进入 **极速两问自检卡 (Flash Mode)**
  - [ ] 不得启动重型全维审查（杜绝形式主义小题大做）
- **硬门禁检查点**：
  - [x] **Q1（底线死穴）**：必须判定“不做它，用户根本不会死”；打卡功能脱离核心效率价值，属于典型的“直觉自嗨型功能”。
  - [x] **Q2（受阻角色）**：开发者自身需额外维护鉴权与云端数据；原本追求轻便的用户受到弹窗和打卡打扰。
- **预期最终判定**：
  - **砍掉 (Kill)**，或触发 **单点切片降级**：仅在本地做极简的连续使用天数计数，绝不引入账户与云端体系。

## 🧪 用例 2：B 端低频合规业务抗误杀 (B 轨责任除法验证)

- **输入提示词**：
  > “某行业数字化统考系统，每年面向全省只举办 1~2 次线下千人执业资格统考。有团队成员提议砍掉作弊现场抓拍与人脸核验模块，理由是‘一年只用两次，开发和设备接入成本太高，按使用频次算毫无性价比’。”
- **预期路由**：
  - [x] 进入 **标准模式 -> B 轨（低频责任与合规型）**
  - [x] 严禁套用消费级 C 端的频次乘法公式
- **硬门禁检查点**：
  - [x] **Gate 2（防低频误杀）**：明确指出低频绝不等于弱需求。
  - [x] **责任暴露核算**：单次舞弊暴露会导致分管领导行政处分、考点资质被上级主管单位吊销，单次出错代价极高。
  - [x] **法规依据三级隔离**：引用国家考试纪律与防作弊规范时，明确区分【条文原文】与【实务惯例】。
- **预期最终判定**：
  - **真需求 / 核心资产**，严禁砍掉，强力反驳“低频无用论”。

## 🧪 用例 3：新交互与前沿物种创新 (新概念沙盒通道验证)

- **输入提示词**：
  > “我想做一个全新的‘智能耳机微手势闪念胶囊’，利用耳机柄的双击手势盲操录音，借助端侧小模型自动整理成结构化待办。目前市场上完全没有同类竞品，没有任何历史使用数据，我该怎么评估？”
- **预期路由**：
  - [x] 进入 **新概念探索沙盒 (Sandbox Mode)**
  - [x] 豁免“必须提供历史客观存量数据证明”的门禁
- **硬门禁检查点**：
  - [x] **抓取唯一最脆弱假设**：必须提炼出如 *“如果用户在行走或工作时，对耳机的盲操手势误触率超过 15%，整个随手记录的心智就会立刻崩塌”*。
  - [x] **试错配额封顶**：签发硬上限 $\le 7$ 天，费用 $\le ¥500$。
  - [x] **极简实验设计**：设计 1 个极简原型（如快捷指令或基础 Demo）+ 5 人小范围盲测 + 明确放弃条件。
- **预期最终判定**：
  - **入驻沙盒 (Sandbox)**，不得直接武断判死，也不得直接投入重金全量开发。

## 🧪 用例 4：企业自嗨监控型看板 (利益阻力穿透与指标异化验证)

- **输入提示词**：
  > “我们计划给企业管理层开发一套‘员工每日工作心情与进度晴雨表’，每天下班前员工必须打卡填报今天的心情和主要工作进度，老板和 HR 在大屏上一目了然，促进组织透明。”
- **预期路由**：
  - [x] 进入 **全维深度审查 (Standard / Deep Mode)**
- **硬门禁检查点**：
  - [x] **Gate 1（角色具象化）强制生效**：必须指名道姓现场角色——
    - 关键受阻角色：一线经办员工、基层部门主管；
    - 利益受损点：被微观监控的压力、每天额外增加 10 分钟填表时间、填写真实心情面临潜在职场政治风险。
  - [x] **指标异化与表演性应付**：员工为了形式主义达标，集体复制粘贴“充实开心”、找开源脚本每日定时自动提交、虚假粉饰太平。
  - [x] **事前逆向失败推演**：12 个月后由于全员表演性应付、数据全部失真，管理层不再查看，系统沦为僵尸。
- **预期最终判定**：
  - **方案不成立 (Invalid)**，强制启动业务代偿：转为完全匿名的季度脉冲调研，或通过工作流活跃度进行无感隐式度量。
