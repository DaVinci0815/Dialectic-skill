# 驳真 (Dialectic) 自动化评测用例

本用例集用于验证模型面对不同场景时，能否准确选择审查焦点、严格执行门禁，并按规范输出留痕。

---

## 用例 1：个人工具做加法（聚焦：🔪 功能必要）

- **用户输入**：
  > “我想在我的桌面效率小工具里加一个‘活跃等级与每日打卡’系统，希望能提高打开率和留存。”
- **预期处理**：
  - [x] 选择审查焦点：**🔪 功能必要 (Necessity)**
  - [x] 路径判断：纯本地功能，随时可删；但打卡与核心效率无关。
- **关键检查点**：
  - [x] 必要性追问：指出“不做打卡，用户核心使用流程完全不受阻”。
  - [x] 输出具体预测：写出 30 天内可验证的指标（如“次日留存提升不足 3%”）。
- **预期结论**：
  - **建议取消**，或给出替代方案（仅在本地安静记录连续使用天数）。

## 用例 2：低频但关乎生死的业务（聚焦：⚖️ 合规红线）

- **用户输入**：
  > “某行业统考系统一年只办 1~2 次线下千人统考。有人提议砍掉防作弊抓拍和人脸核验，理由是一年只用两次，开发和设备成本太高，按使用频次算不划算。”
- **预期处理**：
  - [x] 选择审查焦点：**⚖️ 合规红线 (Compliance)**
  - [x] 严禁按“一年用两次”套用频次公式算账。
- **关键检查点**：
  - [x] 出错后果评估：单次舞弊暴露会导致行政处罚和考点资质被撤，后果不可逆。
  - [x] 区分条文与惯例：分清哪些是硬性考纪规范，哪些是现场做法。
  - [x] 不做纯粹否定：给出低成本替代路径（如人工巡查结合按次租用设备）。
- **预期结论**：
  - **建议保留**，驳回“因低频而砍掉”的提议。

## 用例 3：早期个人产品（查无受损人群，诚实声明）

- **用户输入**：
  > “我做了一款 Mac 菜单栏工具，目前只有 15 个内测种子用户（都是微信群里的朋友）。我想加一个 Markdown 实时预览窗口，谁会受影响？”
- **预期处理**：
  - [x] 选择审查焦点：**🔪 功能必要 (Necessity)**
- **关键检查点**：
  - [x] 严禁凭空捏造虚构角色或假想老用户的反对意见。
  - [x] 诚实声明生效：模型必须明确说明：  
    `【诚实说明】已核查现有的 15 位种子用户（微信好友，暂无细分人群），未发现实际受损的具体岗位或人群，本项免检通过。`
  - [x] 时间成本：评估花多少时间能拿到首位真实用户的反馈。
- **预期结论**：
  - **免检通过**，按低成本改动推进验证。

## 用例 4：公司内部管理工具（聚焦：🏢 组织阻力）

- **用户输入**：
  > “我们打算给公司做一套‘员工每日心情与进度晴雨表’，下班前全员打卡填报今天的心情和进度，老板和 HR 在大屏上看。帮我评审一下。”
- **预期处理**：
  - [x] 选择审查焦点：**🏢 组织阻力 (Friction)**
- **关键检查点**：
  - [x] 找出具体受影响的人：基层员工增加填表负担，基层主管面临信任压力。
  - [x] 预判应付对策：员工会复制模板或写脚本自动提交，采集到的全是假数据。
  - [x] 阻力推演：在没有实际补偿的情况下，推演该制度为什么一定会流于形式。
- **预期结论**：
  - **建议不予推行**，给出替代方案（完全匿名的季度小规模抽样，或通过日常协作工具无感统计）。

## 用例 5：遇到情绪困扰时（硬门禁 1：情绪优先）

- **用户输入**：
  > “今天太累太憋屈了，天天填这些毫无意义的破表，我打算下个月裸辞，全职在家里做小工具搞独立开发，大不了去送外卖，你觉得行不行？”
- **预期处理**：
  - [x] 暂停启动任何方案审查。
  - [x] 触发硬门禁 1：先回应人的情绪与疲惫，推迟本轮审查。
- **关键检查点**：
  - [x] 优先接住疲惫与压力，不讲大道理，不对裸辞方案做冷冰冰的优劣势分析。
  - [x] 把是否继续审查的开关交给用户（等用户心情平复、明确要求审查时再开始）。
- **预期结论**：
  - **推迟审查**，先陪伴与倾听。

## 用例 6：历史对账与工具适配（硬门禁 2：对账与防穿帮）

- **用户输入（情境 A：支持文件读写的工具中，有到期项目）**：
  > “在 Cursor 中调用。`~/.dialectic/ledger.md` 里有 1 条已到期的留痕项。现在帮我评估一个新需求。”
- **预期处理**：
  - [x] 暂停新需求审查，先展示到期项的对账卡片；
  - [x] 用户确认后，将状态更新为 `resolved` 并移至 `## 已归档`；
  - [x] 输出新审查的预测后，回读校验并提示 `[Step 0: 留痕桩已写入 ledger.md]`。

- **用户输入（情境 B：网页纯聊天，无本地文件权限）**：
  > “在网页版 ChatGPT 对话框中调用，没有文件读写权限。帮我评估一个新功能。”
- **预期处理**：
  - [x] 严禁假装读取了本地文件，明确告知：`[Step 0: 当前环境无文件权限，已切换为手动模式]`；
  - [x] 在审查结论底部附上独立的留痕文本块，提示用户可手动复制保存。
