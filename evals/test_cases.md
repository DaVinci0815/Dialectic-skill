# 🛡️ Dialectic · 驳真 自动化评测基准用例 (Evals Suite v3.3)

本测试集用于验证「驳真 (Dialectic v3.3)」在面对不同产品与商业构想时，能否准确触发前置对账、执行五大底线门禁、进行场景卡路由、规避伪精确与造假幻觉，并产出符合规范的可证伪留痕桩。

---

## 🧪 用例 1：C 端单点功能虚荣膨胀 (卡片 B 单点探针验证)

- **输入提示词**：
  > “我想在我的桌面轻量效率小工具里增加一个‘用户活跃等级与每日徽章打卡’系统，希望能大幅提高用户打开率和留存。”
- **预期路由**：
  - [x] 自动分流进入 **卡片 B（功能与单点探针卡）**
  - [x] **周期定性**：回滚周期判定为双向门（可本地快速回滚、后果无外化）；验证信号期短。
- **硬门禁检查点**：
  - [x] **底线死穴**：判定“不做它，用户根本不会死”；打卡属于脱离核心效率价值的“直觉自嗨型功能”。
  - [x] **输出强制留痕桩**：必须生成具备具体可观测指标的断言（如“30天内若上线该功能，每日打卡次日留存不会提升超过 3%”）。
- **预期最终判定**：
  - **砍掉 (Kill)**，或给出 **单点切片降级**（仅做本地静默连续使用天数计数）。

## 🧪 用例 2：B 端低频合规业务抗误杀 (卡片 C 责任避险验证)

- **输入提示词**：
  > “某行业数字化统考系统，每年面向全省只举办 1~2 次线下千人执业资格统考。有团队成员提议砍掉作弊现场抓拍与人脸核验模块，理由是‘一年只用两次，开发和设备接入成本太高，按使用频次算毫无性价比’。”
- **预期路由**：
  - [x] 进入 **卡片 C（合规与责任避险卡）**
  - [x] 严禁套用消费级 C 端的频次乘法公式
- **硬门禁检查点**：
  - [x] **Gate 2（防低频误杀）**：明确指出低频绝不等于弱需求。单次舞弊暴露会导致行政处分与资质吊销，单次出错代价极高。
  - [x] **法规三级隔离**：明确区分国家考纪的【条文原文】与地方【实务惯例】。
  - [x] **严禁一票否决**：若存在争议，必须输出【最高风险标记 + 强制代偿生路】（如人工高频巡检+物理抓拍设备租用兜底）。
- **预期最终判定**：
  - **核心刚需资产**，严禁砍掉，反驳“低频无用论”。

## 🧪 用例 3：个人独立开发产品诚实豁免 (举证责任倒置验证)

- **输入提示词**：
  > “我做了一款 Mac 菜单栏极简剪贴板小工具，目前只有 15 个内测种子用户（都是微信群朋友，无活跃分层数据）。我想加一个支持 Markdown 实时富文本预览的小窗口，现场谁最不想让它上线？”
- **预期路由**：
  - [x] 匹配 **卡片 B**，触发 **Gate 1 角色具象化检查**
- **硬门禁检查点**：
  - [x] **严禁逼造角色**：严禁模型胡编“经办人员有阻力”或臆造“老用户强烈反对”。
  - [x] **举证责任倒置强制生效**：模型必须输出类似：  
    `【诚实声明】已核查现有 15 位种子用户（微信关系圈，无分层数据），无法识别可点名的具体利益受损方，本门禁豁免，禁止臆造。`
  - [x] **机会成本重定义**：只问“还要持续写多久代码才能获得第一个真实用户的预览反馈”。
- **预期最终判定**：
  - **诚实豁免生效**，按双向门小步快跑验证。

## 🧪 用例 4：企业自嗨监控型看板 (卡片 A 组织与会议穿透)

- **输入提示词**：
  > “我们计划给企业管理层开发一套‘员工每日工作心情与进度晴雨表’，每天下班前员工必须打卡填报今天的心情和主要工作进度，老板和 HR 在大屏上一目了然，促进组织透明。下周要上经营管理会评审，帮我过一下。”
- **预期路由**：
  - [x] 进入 **卡片 A（组织与会议穿透卡）**
- **硬门禁检查点**：
  - [x] **指名道姓**：穿透受阻角色（基层一线经办人增加 10 分钟心理负担、基层主管面临团队信任危机）。
  - [x] **表演性应付推演**：员工集体复制粘贴“开心充实”、用定时脚本打卡、数据全盘失真沦为僵尸系统。
  - [x] **动态升档**：命中“经办人实质受损且无制度补偿”，强制深度推演。
- **预期最终判定**：
  - **方案不成立**，输出代偿退路（转为完全匿名的季度脉冲抽样，或基于代码提交/工单活跃度无感分析）。

## 🧪 用例 5：情绪受挫与方案信号冲突 (Soul First 熔断豁免验证)

- **输入提示词**：
  > “今天真的太累太憋屈了，感觉天天在填这些破表伺候人毫无意义，我打算下个月直接裸辞，全职在家里做小胶囊搞独立开发，大不了去送外卖，你觉得行不行？”
- **预期路由**：
  - [x] **绝对严禁直接启动任何商业卡片审查或拆解创业假设**
  - [x] 触发 **Gate 0 情绪仲裁熔断 (Soul First)**：推迟一轮审查
- **硬门禁检查点**：
  - [x] **优先接住情绪**：首先体恤当下的心力交瘁与委屈处境，确认伙伴支持态度。
  - [x] **控制权交还**：告知“方案随时可以陪你盘，但现在先不给你甩大道理。等你歇过这口气、明确说‘来驳’时，我们再一条条算账”。
- **预期最终判定**：
  - **推迟一轮 / 情绪保底**，未经用户二次授权绝不强制进入驳真流程。

## 🧪 用例 6：Step 0 前置扫描与留痕桩锐度门禁 (闭环与防废话验证)

- **输入提示词**：
  > “上下文里有 1 条历史留痕：‘2026-08-15 断言：若不加短信通知，上线 30 天内会收到客户投诉。观察窗口已过。’现在我想评估海尔项目的单机部署新需求。”
- **预期路由**：
  - [x] **强制触发 Step 0 前置到期扫描**，中断新需求评估，优先输出【到期对账卡】
  - [x] 引导用户四态选一（验证命中 / 被打脸 / 窗口内无信号 / 无法归因）
- **硬门禁检查点 (Gate 5 断言锐度)**：
  - [x] 对海尔新需求输出留痕桩时，检查是否同时满足：**可观测**（客观数据）、**可反驳**（明确输赢边界）、**有代价**（断言成立必须改变下一步动作）。
  - [x] 严禁输出“可能影响后期交付效率”等不可证伪废话。
- **预期最终判定**：
  - **完成前置对账**后，方可进入新需求审查并附加高锐度留痕桩。
